Case study

Coast Internet Radio

A live redevelopment for a small Newry radio station. I worked directly with the owner on what listeners needed, then built the site and the technical pieces behind it.

What I was solving

The station needed a site that felt straightforward on both desktop and mobile, but the bigger problem sat underneath the layout. The audio stream and now-playing feed were served over plain HTTP while the website itself was HTTPS, so modern browsers blocked them as mixed content.

I put Cloudflare Workers in front of those sources and served them securely to the site. That gave the front end a stable HTTPS path for both the live stream and metadata.

What I built

The listener side includes the stream player, now-playing information, recent tracks, show information and mobile-friendly controls. I also built an admin area so the station owner can update day-to-day content without changing code.

The admin side uses signed sessions, CSRF protection and rate limiting. Content and feedback are stored through Netlify services, while scheduled functions record play history.

One useful failure

While checking the live site I found that an inline script had changed without the matching Content Security Policy hash being updated. The result was subtle: saved display preferences could be blocked before the page rendered.

I fixed the hash, then added a build check that recalculates those hashes so the same mistake fails during validation instead of reaching the live site.

What I would improve next

The next useful improvement would be stronger end-to-end coverage for the admin area. The core paths work, but some release checks still depend on manually clicking through the interface.
