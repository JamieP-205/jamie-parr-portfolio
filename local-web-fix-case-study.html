Case study

Local Web Fix

A small service website I built around a simple idea: help local businesses fix practical website and online-information problems without pretending every job needs a full redesign.

Why I built it

Small business websites often have ordinary problems that still get in a customer's way: opening hours are inconsistent, a menu is hard to find, a phone link is awkward on mobile or an old booking link is still public.

I built Local Web Fix around those smaller jobs and made the limits clear instead of presenting it as a full agency service.

What the site actually does

The first step is a free check using public links only. The site then explains fixed £50, £100 and £150 options for small agreed pieces of work. It also says what is outside the scope and tells clients not to send passwords.

The enquiry flow uses Netlify Forms. The payment page is deliberately unlisted and marked noindex, because it is only meant to be sent after a scope has been agreed.

What the code actually is

The site is deliberately simple: static HTML and CSS with a small JavaScript theme toggle stored in localStorage. There is no application framework or unnecessary backend.

The repository includes checks for required pages, local links and the Netlify form setup so a small markup mistake is less likely to break the enquiry path unnoticed.

What I learned from it

The harder part was deciding what to say and what not to promise. Pricing, access rules and scope have to make sense to somebody who does not care what technology the site uses.

It also pushed me to leave the implementation small. Adding more features would not automatically make the service clearer or more useful.

What I would improve next

The biggest gap is evidence from real jobs. The example check is clearly labelled fictional, so the next useful addition is a real before-and-after report once a client is happy for me to publish one.
